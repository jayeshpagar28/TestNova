TESTNOVA · HOW THE AGENTS WORK

Eight specialised agents.
One testing lifecycle.

Each stage is its own Claude agent with its own role, instructions and tool permissions. Agents hand work to each other through files in the project workspace. The orchestrator checks every handoff before the next stage starts.

1
BA Agentba-explorer
Reads the uploaded docs, links and notes, then explores the live app in a real browser
→ user stories + screenshots
2
BA Agent 2.0knowledge-base-builderhuman review
Builds the project knowledge base: modules, roles, flows, business rules, validations, gaps. Every fact cites its source
→ knowledge-base.json (drives the dashboard modules)
3
Test Plannertest-plannerhuman review
Per-module plans: happy path, negative, validation, business rules, responsive, network failure, accessibility
→ test case tables
4
Human-Like Testingexploratory-testerhuman review
Runs the plan by hand in a browser, like a senior tester, before any script exists
→ pass / fail / blocked + console & network evidence
5
Test Generatortest-generator
Writes Playwright Test automation on a Page Object Model. The stage only passes if the TypeScript typecheck passes
→ pages · components · fixtures · specs
6
Test Healertest-healer
Executes every module, fixes broken scripts in the right layer and re-runs. Never weakens an assertion: a real bug is tagged, not hidden
→ real executions on the dashboard
7
Defect Analysisdefect-analyst
Classifies each failure as App defect, Script, Environment or Test data, and reads console errors, 4xx/5xx and accessibility violations
→ defect register + Excel sheet
8
QA Reportqa-reporter
Writes the narrative. The report engine produces the figures, defect register and evidence
→ PDF + Excel report

Orchestrator

  • Node.js server runs stages through the Claude Agent SDK
  • A stage passes only when its output files exist and validate, not when the agent says it is done
  • Checkpoints for resuming after interruptions
  • Process guard hook on every shell command

Execution

  • Playwright Test (Chromium, Firefox, WebKit)
  • Playwright MCP for agent browsing
  • Custom reporter streams live results
  • Evidence per test: screenshot, trace, video, web signals, axe-core scan

Reporting

  • React 19 + Vite + Tailwind dashboard
  • One report model feeds the dashboard, PDF and Excel
  • Plain-language failure explanations
  • Supabase mirror + sign-in for remote viewers

People stay in charge

Optional review gates after stages 2, 3 and 4. QA engineers review the knowledge, the plan and the findings before automation is generated.
